# Classroom study mode — Fourth Down Lab

## Purpose
Within-subjects pilot/exploratory study comparing **static probability table** and **interactive D3 bars**. Both provide precisely the same three WP values. The comparison tests presentation and interaction rather than differences in information content or model performance. The target outcome is recognition of close decisions (`top-two gap < 2 percentage points`). Not an IRB-approved clinical/scientific study or a test of truly optimal NFL decisions.

## Study URL
Run `python app.py` and open `http://127.0.0.1:5001/study` on the Mac hosting Flask. The original six-section main dashboard remains at `/`.

## Implementation
- Twelve fixed fictionalized game states computed by the current app model: 6 in set A, 6 in set B, each 3 close and 3 clear cases.
- Each participant completes six static and six interactive scenarios, with two usability surveys (after each block) and final preference.
- Participant numbers 1, 2, 3, 4 respectively implement allocations: A/static→B/interactive; A/interactive→B/static; B/static→A/interactive; B/interactive→A/static. These repeat for every 4 IDs.
- Same task items each trial: best estimated action, numeric top-two gap, gap strictly below 2 pp; 1 timer per trial.
- Generated file `static/data/study_scenarios.json` contains expected answers and predictions. It is deliberately not hidden from the participant's browser; run this as a cooperative classroom usability study, not as a secure proctored exam.
- Data never leaves browser automatically. Participants download 12-row CSV with anonymous ID, actual/expected answers, correctness, task time, after-block usability responses, and optional feedback. The facilitators must collect these files manually, with consent and institutional/course guidance. No IP/name/email collected by the study code; local browser/server/network logs may still be generated by the hosting environment.

## Pilot check before recruiting
1. Use ID **9999** for a pilot (excluded automatically by analysis script). Complete all 12 tasks, both 5-item surveys, and download CSV.
2. Confirm CSV has exactly 12 data rows, one row per task; `condition` has six of each value; timing and correctness fields populated.
3. Check hovering over interactive bars, static table numbers, button progression, survey entry, and CSV download on the browsers intended for the study.
4. Do not refresh mid-study or the in-memory results are lost. Participants can stop or close the tab without exporting.
5. The D3 library is loaded from a CDN; internet is needed for the interactive chart. If blocked, do **not** run trials: arrange local D3 hosting first.

## Conduct
Use anonymous numeric IDs, counterbalance them in batches of four, and keep participant assignment separate from identifying information. Don't use screenshot/benchmark values as true decision ground truth. Obtain course/institution guidance on consent and recruitment before involving volunteers. Don't use the original dashboard during task sessions (it displays additional results not available to baseline condition).

## Summary script
Create `study/results/`, place participant CSV exports inside it, then run:

```bash
python study/analyze_study.py
```

This summarizes paired participant means for best-choice accuracy, close-call classification, absolute numerical gap error (pp) and seconds per task. Excludes pilot ID 9999 and incomplete paired participants. Output `study/results/combined_study_results.csv`. Treat with modest sample as descriptive/exploratory, not robust causal proof.

## Reproducibility and limitations
The answer key is fixed at build time using the trained model and uploaded 2022–24 outcome distributions. If the model or outcome CSV changes, use `python study/generate_study_scenarios.py` to regenerate it **before** a study begins; never change questions mid-collection. The scenarios are model outputs, not observed historical coaching decisions or true counterfactual optimal actions. Scoring is relative to these model outputs. Accuracy measures comprehension of the model display, not prediction of real game outcomes.
